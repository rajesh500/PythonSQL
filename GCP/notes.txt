storage class: BY depending on frequency of accessing your files we have to select our storage class.
standard storage: by using this class we can access our files on daily basis [more money]
Nearline storage: by using this class we can access our files on monthly basis
Coldline storage: by using this class we can access our files on quarterly basis
Archive storage: by using this class we can access our files on yearly basis [less money].
Rapid:  Best for highest frequency reads and writes. Only available for zones.


Location: 
	Single Region: Your data would be available in only single location of GCP datacenter. [Mumbai - single region] [Non high availability feature]
	Multi region: Your data would be available in multiple locations of GCP datacenter. [US,UK,In]     [Highest Availability]
	Dual region: Your data would be available in only two locations of GCP datacenter. [US,In]         [High availability]

Enabled Rapid cache: Optimize for workloads where infrequently changed data is frequently read, such as ML model training or analytics. we can able to create Hadoop clusters or spark clusters automatically.
Dataproc to Managed Service for Apache Spark

Dataproc: Google dataproc is a managed apache spark and apache hadoop service that simplifies the process of creating and managing clusters for bigdata processing and analytics. It allows you can quickly create and manage and scale cluster while taking advatnage of power of open source data processing framework.

Features of Dataproc:
--------------------
1. Managed clusters: Dataproc takes care of cluster creation/scaling and management ..with that you can focus more on dataprocessing related tasks.
2. Support for open source frameworks: It supports apache spark, apache hadoop, apache pig and apache hive ...
3. Integrate with GCP services: 
		Dataproc + GCS
		Dataproc + compute engine
		Dataproc + bigquery
		Dataproc + composer 
4. Customization: WHile creation of the cluster you can specify configuration of your cluster.
	- single node cluster [single VM] [Same machine will act as team lead (master) and team member (worker)]
	- multi node cluster [More than one VM (10 VM) ==> 1 VM master machine and all other machines are going to act as worker machines]
	Master machine ==> Team lead [manage all the team mmbers/assign tasks/Details of Team members]
	Worker machine ==> Team members
